# TextureDedup By 月华

TextureDedup 是一个本地运行的贴图查重工具，提供网页界面和 Windows 桌面封装。仓库只包含源码；缓存、模型、测试数据和打包后的 EXE 不纳入 Git。

## Windows 版下载

从 [GitHub Releases](https://github.com/jingshi321/TextureDedup/releases/latest) 下载 `TextureDedup.exe`，双击运行，无需安装 Python。支持 Windows 10/11 64 位，需要 Microsoft Edge WebView2 运行时。内置本地 AI 模型，优先使用 DirectML GPU，不可用时回退 CPU。缓存保存在 Windows 临时目录，正常关闭后清除本次缓存。发行页面同时提供 SHA256 校验文件。

## 从源码运行

需要 Python 3.10 或更新版本。安装核心依赖后运行 `启动贴图查重.cmd`：

```powershell
py -3 -m pip install -r requirements.txt
py -3 server.py
```

本地 AI 检索需要运行 `py -3 setup_ai.py` 下载依赖和模型；首次运行需要联网。Windows 桌面 EXE 的构建还需要 WebView2 和 PyInstaller 相关依赖，生成文件输出到 `Windows版/`，构建缓存放在 `save/`。预编译 EXE 在上述 Releases 页面下载。

修复确认删除后文件未被回收的问题：扫描为加速而延后计算完整文件哈希时，清理会先核对扫描时的完整 RGBA 像素校验值，再补齐文件哈希，用于后续检查；文件发生变化仍拒绝执行。清理失败原因保留在确认窗口，执行过程中显示实际进度并禁止重复确认。确认窗口可按住标题拖动，位置限制在当前可见区域；进度同时覆盖文件核对和移入回收站，显示总百分比与已回收文件数。执行期间禁止另一次扫描、移动或清理，关闭软件会等待清理结束。

本次优化让外观比较的任务跨图片补满线程池，每批在途比较最多为工作线程数的4倍；缩放校验顺带计算内容分数，供最终评分复用。同一批中需要多个比较尺寸的图片只解码一次，所有尺寸直接从原图生成，保留透明像素下的 RGB 及原来的相似度算法。比较数组仍限制为64 MiB，多尺寸预热每批最多使用其中一半；无损中间图像的压缩载荷上限仍为1 GiB，达到上限自动回退直接读图。所有中间数据同样属于关闭时清除的临时缓存。

大目录扫描还会按文件大小延后完整 SHA256：不同大小的文件不可能是字节级完全重复，因此只对存在同大小候选的文件计算完整文件哈希。图片解码线程会根据 Windows 当前 CPU 负载在 4 到 12 个线程之间按批次调整，负载高时降档，空闲时升档。线程上限、缓存容量和取消退出逻辑均有限制。

外观候选的缩放校验已使用受限 CPU 线程池并行执行，数据库写入仍由扫描线程串行完成，避免 SQLite 竞争；GPU 仍用于本地 AI 推理。1,020 张样本的外观比较阶段约由 3.35 秒降至 0.72 秒，候选分组和评分一致。

与上一版 GPU 版本交替测试同一批 1,020 张贴图，每轮空索引、先预热驱动、各两轮：开启 AI 的总扫描平均 10.73→9.41 秒（耗时减少约 12%）；关闭 AI 平均 5.02→4.74 秒（减少约 5%）。两种模式下候选分组、最终内容评分及保留文件均一致。小样本结果不能代表整库；报告为 save/reuse-balanced-timing.json。

本地 AI 优先使用 DirectML GPU 加速，不可用时自动回退 CPU；通过批量推理及并行读取图片提高速度。默认勾选“AI 仅检索特效候选”，仅限制 AI 检索范围，其他查重仍扫描全部支持的图片；取消勾选即可对全部贴图进行 AI 检索。候选识别依据路径及文件名，可能漏选，请按需要关闭。关闭后仍清除本次缓存，不跨启动保留 AI 特征。

本机 RTX 4080 对同一批 2,000 张真实贴图的无特征缓存测试：旧版 CPU 逐张提取 31.74 秒，新版 GPU 批量及并行预读 12.64 秒，AI 特征提取约快 2.51 倍，结果特征余弦相似度最低 0.99999982。这是 AI 特征提取阶段的测试，不代表整个扫描流程的倍数；报告位于 save/ai-benchmark.json。

独立版每次在 Windows 临时文件夹创建专用 `TextureDedup-随机字符` 目录，保存扫描索引、结果和 WebView2 缓存；正常关闭后自动清理自己的缓存。关闭时停止扫描，等待正在执行的移动操作结束。下次打开需重新扫描。选择记忆保留到本次扫描结果失效或关闭软件，切换类别、相似度及通道不会丢失选择。软件不会清理其他临时文件或原网页版 save 目录。

原网页版仍可双击 **启动贴图查重.cmd** 使用，它依赖本机 Python，缓存继续保存在项目 save/ 下。

## 使用

1. 选择贴图目录或粘贴路径，每行一个，扫描包含子目录。扫描目录默认为空。
2. 默认启用完整文件、RGBA 像素和外观查重。需要神经网络视觉检索时勾选“本地 AI 相似检索”。
3. 点击开始查重。首次扫描读取所有像素，AI 额外生成特征；后续重复扫描复用索引。
4. 在结果中切换类型和 RGBA、RGB、Alpha、R、G、B 通道。点击打开目录或复制路径定位原文件。
5. 在各类别中选择每组要保留的文件；未选文件标为删除目标。切换类别、相似度及通道会记住选择；“清空选择”和“删除未选文件”只处理当前筛选，其他筛选记住的文件不参与本次操作。

点击“选择所有特效贴图”，按资源目录和文件名筛选特效候选，排除技能图标、UI、装备、场景和常见材质通道贴图；只因火焰、闪电、光束等宽泛名称命中的图片暂不自动选，用途不明确的不选。预览滚动时自动加载更多缩略图。该规则偏保守，只以 fire / lightning / beam 等宽泛词命名的图片可能落入“用途不明”，避免把装备材质误选；点击“移动”才选择目标目录并移动这份已预览的选择清单，保留子目录结构，同名跳过；预览后新增文件不会被移动。跨盘移动先复制并校验再移走源文件，操作结束后重新扫描。

软件新增经确认后移入 Windows 回收站的功能，不会自动清理。扫描和对比过程只读。原网页版的索引、模型、依赖、临时文件、测试样本及扫描结果缓存放在软件目录的 **save/** 下；独立 EXE 使用前述 Windows 临时目录。源文件读取时不会生成旁车文件。CSV、JSON报告导出按钮和接口已移除。

## 判定含义

- 文件完全重复：完整文件 SHA256 相同。
- RGBA 像素重复：尺寸和解码后的每个 RGBA 字节相同，容器压缩和文字元数据可以不同。与文件重复组可能重叠。
- 外观相似：DCT 感知哈希、宽高比及缩小后的原始 RGB 平均差共同筛选；默认还检查 Alpha 哈希和平均差。比较缩略图时保留完全透明处的隐藏 RGB。
- AI 近似：MobileNetV2 的 1280 维池化特征，余弦相似度筛选。图片合成到灰色背景后送入模型；严格 Alpha 选项仍会额外检查透明度。模型预训练于 ImageNet，并非专门的贴图模型。

搜索算法用于寻找候选；页面的相似度统一使用下文的图片内容分数，不是“有多大概率为重复”。同一贴图的完全一致副本会先合并为代表，外观及 AI 仅比较各代表，相关全部副本请查看精确组。相似组显示两张候选，避免把 A≈B、B≈C 自动推断为 A≈C。

AI 使用 8 组随机投影哈希表检索候选，避免全库矩阵比较，**属于近似检索，会漏检**；不处理旋转、翻转等变换的完整穷举。大量相似候选会导致耗时增加，相似候选到 50,000 组后停止相似搜索并提示；精确重复组不受此上限影响。严格 Alpha 比较也是缩略图启发式，只有“RGBA 像素重复”表示完整 Alpha 相同。

支持 PNG、TGA、Pillow 可解码的 DDS/TIFF、BMP、JPEG、WebP。多帧文件跳过并记录错误；HDR/16位通道会被转换成8位 RGBA比较，不保证原始高精度数据相同，因此请以文件 SHA256 确认高精度原件。自定义压缩 DDS 可能无法解码。大型图片受 Pillow 解压保护限制，错误可在页面底部的“读取问题”中查看。

缓存以路径、文件字节数和修改时间识别是否变化；若文件内容变了但大小、修改时间均被保留，勾选“重新读取文件”。上次完成结果保存在 save/last-result.json，重启可继续浏览；缩略图读取当前源文件，源文件后来改动时应重扫。

## 验证

`python -B test_app.py`：验证完整文件重复、不同 PNG 编码的相同 RGBA、不同 Alpha 区分、明显颜色差异排除、重叠目录去重、缓存刷新、实际 ONNX 推理、取消及 HTTP 缩略图/API 令牌、导出接口移除。

`validate_real.py` 是可选的本地数据验证脚本。先设置 `TEXTUREDEDUP_TEST_IMAGE_DIR` 为自己的图片目录，再运行 `python -B validate_real.py`；脚本复制最多150张 PNG 到 save/real-sample 后测试，不改动源图片。测试和缓存会占用空间，程序不自动删除任何文件。


## 新增：缩放分类与清理

开启“等比例缩放 / 非等比例拉伸”，可检测内容经等比例缩放或横纵拉伸的候选。候选先用感知哈希筛选，再把原始 RGBA 各通道缩到共同尺寸比较（平均误差≤0.012、95%分位误差≤0.04），不丢弃透明区域隐藏的 RGB。宽高比完全相同归为等比例，否则归为非等比例。插值、裁剪和压缩会影响判断；这些组仍标记为候选，需要人工核对。此筛选不能保证找全，极细微的差异也可能被低分辨率比较掩盖。

每组默认选择**文件字节数最大**的成员作为保留项；同样大小时按单选按钮确定保留哪一张。该组其余未选文件都是删除目标，即使字节数相同也会列入清单。最大字节数不代表分辨率或画质最高。

“选择文件最大的贴图”选择当前类别及相似度筛选下的全部组，包括未加载的组。缩放与拉伸候选应核对后再清理；普通外观相似和 AI 近似组只支持选择和比较，清理预览会跳过并提示数量。

点击“删除未选文件”查看完整保留/回收路径、数量和字节数，再点击确认才执行。清单五分钟有效且只能执行一次。仅当前筛选内已选组参与清理；重叠组按每组选择逐一生成删除目标：任何已选组中未选的文件都会列入清单，不会被另一组的保留选择或相同字节数挡住；清单会去重。其他筛选记住的选择不会参与本次操作。执行前每个目标和实际保留文件各校验一次；随后分批移入回收站，避免重复读取所有保留文件。文件大小或修改时间变化会拒绝，执行中遇错立即停止并报告已完成数量。移入回收站失败不会回退为永久删除，操作日志写在 save/recycle-*.jsonl。回收站恢复可在 Windows 中操作。完成后立即移除成功回收文件的缩略图，同步更新贴图总数、组内数量及各类别组数，无需重新扫描。只剩一张贴图的组自动消失；仍有两张以上的组继续显示。删除后清除已消失组、或保留图已被删除的记忆，其余选择继续保留；部分失败时仅移除已成功回收的文件。

新增依赖 Send2Trash，其许可随 save/deps 发行包保留。76项回归测试通过；使用自行生成的图片验证了批量回收、同大小文件按未选状态清理、部分失败报告和打包 EXE 的 Windows 回收站流程，未对原始贴图库实际执行清理。


## 最低相似度筛选

“全部结果”按类型交替展示，让有结果的各类型在前几页都可见；单独选择某类型时仍按原有组顺序展示。下拉选项显示当前相似度筛选后的各类组数，向下滚动到底部附近会每批追加12组，底部也可手动点击“加载更多”，显示已加载/总组数；直到所有符合筛选条件的组都可连续浏览。修改类型或最低相似度重新加载首批，切换预览通道保留已加载范围。0组表示没有符合条件的已发现结果；未启用AI检索的扫描不会产生AI组。混合显示只调整浏览顺序，不改变分组或相似度。

在结果工具栏填写“最低内容相似度”，例如 **99** 表示只显示 **内容相似度 ≥99%** 的已有组；支持 0–100 的小数，只保留一个相似度输入框。0 显示全部评分成功的组。输入或使用数字箭头修改后立即更新，无需按回车或移开焦点，也无需重新扫描，分页按当前类型及相似度筛选。更改类型、相似度或通道保留每组选择；工具栏显示当前已选数，有隐藏选择时也显示记忆总数。批量选择会更新当前筛选的所有组并保留其他选择；清空和删除只作用于当前筛选，隐藏组不会作为删除候选，其中记住的保留文件也不参与本次保留。

内容分数统一比较图片的 RGB 通道，保留透明区域的隐藏 RGB。不同尺寸先将各通道缩至共同尺寸，每边最多256像素，再计算归一化平均绝对误差；分数为 `(1－误差)×100%`。启用严格 Alpha 比较时，分别计算 RGB 与 Alpha 的误差，取误差较大的一项评分，避免相同透明度抬高 RGB 分数。例如99表示平均通道误差不超过1%，不表示99%的像素完全相同，也不是重复概率；缩小比较可能掩盖细节，100%内容分数也不能保证原文件完全相同。只有精确重复类型提供文件/像素完全相同判断。

旧结果首次启动会自动重新计算内容分数并在 save/ 备份原结果，无需重新搜索整库。之后筛选即时生效。内容评分按完整 RGBA 内容哈希、尺寸、算法版本及 Alpha 选项缓存在 save/index.sqlite；源文件大小或修改时间变化时，该组暂不参与筛选并报告需要重扫。

筛选只作用于已经发现的结果，不能找回扫描阶段被阈值或候选上限排除的图片。需要更多候选时调整比较参数后重扫；AI 初始阈值为97%，若想查找更低相似度的 AI 候选，请降低该扫描阈值。

## 扫描速度优化

新增整库分组缓存：每次扫描仍检查目录、文件大小和修改时间；贴图清单与比较参数完全一致时，直接复用此前的分组和内容分数，跳过候选搜索及评分。新增、移走、修改贴图或改变比较参数时重新比较；勾选“重新读取文件”会绕过复用。缓存有算法版本标识，版本变化后重新计算。遇到读取错误的结果不复用，以便下次重试失败文件。

首次内容评分按 CPU 负载和可用内存动态分配线程，最多24个并行处理，每批最多128组，共享最多64 MiB的比较数组缓存；数据库读写由主线程负责。每张源文件的初始信息检查在评分阶段复用，实际重新计算后再次检查源文件是否变化。已有评分仍从SQLite缓存读取，评分公式、候选规则和清理限制不变。

外观比较现在跨多张代表图组成受限批次，避免每张图只有1至3个候选时多数线程空闲；单张图候选很多时也不会无上限提交任务。输出仍按原来的候选顺序创建组，保留50,000对上限及取消操作。缩放校验产生的本次内容分数使用同一 RGB/Alpha 公式，即使勾选重新读取也可在本次扫描内复用，旧数据库缓存仍会被跳过；每次复用前重新校验源文件大小和修改时间。同批中同一图片的多个缺失尺寸合并解码，直接从原图分别做 BOX 缩放；预热失败由正常比较路径报告，缓存预算不足时自动按需读取。

本轮56,798张贴图、关闭AI、全新扫描数据库的实测总耗时为545.363秒（9分05秒），相对此前581.369秒记录缩短6.19%；外观候选140.141→119.597秒，内容评分110.969→89.429秒。33,965组、全部记录、保留文件、顺序与内容分数逐项一致，分数最大差0、错误0。66项自动测试通过；380张样本的8组选项×4种缓存/刷新路径全部与旧版一致。数据位于 save/speed-v5/full-final/report.json。该数据与历史记录对比，Windows文件缓存可能预热；读图初期曾与额外样本测试短暂重叠，已终止并记录于 save/speed-v5/benchmark-note.json，因此不是严格控制负载或冷盘的测速，也未测AI全库速度。读图与特征仍占本次耗时约61%，整体提速小于比较阶段的提速。

此次本机验证：1,200组真实候选首次内容评分约27.55→10.13秒；48张缩放样本首次扫描约1.72→0.75秒，再扫约0.045→0.014秒，分组和分数逐项一致。150张真实小样本首次约0.66→0.71秒，未提速。56,799张实际贴图、47,350组的未变化结果复用约16.42秒，仍包含目录及文件信息检查。报告位于 save/speed-v2/；样本速度不代表所有贴图库。
